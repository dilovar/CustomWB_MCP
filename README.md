# CustomWB_MCP — аналитический слой данных Wildberries (read-only)

MCP-сервер на C# (ASP.NET Core), который отдаёт Claude данные кабинета WB для антикризисного аудита:
продажи, финансы, остатки, цены, воронка, реклама, отзывы — объединённые по nmID, с паспортом данных.

**Граница ответственности:** сервер только ЧИТАЕТ и агрегирует данные. Все расчёты (юнит-экономика,
ABC, диагностика, рекомендации) и HTML-отчёт делает Claude в диалоге. Записывающих операций нет.

## Структура

```
CustomWB_MCP/
├── CustomWB_MCP.csproj
├── Program.cs                 — DI, named HttpClient на каждый WB-домен, токен из user-secrets, /mcp
├── Wb/
│   ├── WbClients.cs           — домены WB по категориям
│   ├── WbHttp.cs              — GET/POST с ретраями (429 Retry-After, 5xx backoff)
│   ├── JsonExtensions.cs      — защищённый парсинг полей
│   ├── DataPassport.cs        — паспорт данных (получено/частично/нет прав/ошибка)
│   ├── Models.cs              — компактные DTO
│   └── WbGateway.cs           — типизированные read-only методы ко всем источникам
└── Tools/
    ├── PingTool.cs            — проверка связи
    ├── DataTools.cs           — по-категорийные инструменты (каталог, продажи, остатки, финансы, цены, воронка, реклама, отзывы)
    └── AuditTool.cs           — ФЛАГМАН wb_audit_dataset: единая таблица по SKU + паспорт
```

## 1. Токен WB

В ЛК продавца создай токен (тип **Базовый**, доступ **Только чтение**) с категориями:
**Контент, Статистика, Аналитика, Продвижение, Цены и скидки, Отзывы и вопросы**.

Токен читается из конфигурации `Wildberries:Token`. Источник — на выбор, код один и тот же:

**Вариант А — переменная окружения (работает и локально, и на сервере):**
```bash
# Linux/macOS
export Wildberries__Token="<твой токен>"
# Windows PowerShell
$env:Wildberries__Token="<твой токен>"
```
Обрати внимание: в имени переменной **двойное подчёркивание** `__` вместо двоеточия.

**Вариант Б — user-secrets (только для локальной разработки):**
```bash
cd CustomWB_MCP
dotnet user-secrets init
dotnet user-secrets set "Wildberries:Token" "<твой токен>"
```
Папка `user-secrets` **создаётся только после первой команды `set`** — пустой её не существует.
Если не находишь — просто используй Вариант А, он проще и один для всех сред.

## 2. Запуск

```bash
dotnet restore
dotnet run
```
Сервер: `http://localhost:5000`, MCP-эндпоинт: `/mcp`.

## 3. Локальная проверка (до Claude)

```bash
npx @modelcontextprotocol/inspector
```
Транспорт **Streamable HTTP**, адрес `http://localhost:5000/mcp`. Вызови `ping`, затем `wb_get_sales`,
`wb_get_catalog`, и наконец `wb_audit_dataset`.

## 4. Публичный доступ — два пути

### Вариант A — Railway (рекомендуется: постоянный HTTPS, без ngrok)

В проекте есть `Dockerfile` — Railway соберёт по нему.

1. Залей проект в репозиторий GitHub.
2. В Railway: **New Project → Deploy from GitHub repo** → выбери репозиторий.
3. Railway сам увидит `Dockerfile` и соберёт. Порт подхватится из `PORT` автоматически.
4. **Variables** → добавь:
   - `Wildberries__Token` = твой токен WB (двойное подчёркивание!)
   - `Mcp__Path` = `/mcp-<случайная строка>` — приватный путь (напр. `/mcp-9f3k2a`)
5. Railway выдаст публичный HTTPS-адрес вида `https://<app>.up.railway.app`.
   Твой MCP-эндпоинт = этот адрес + значение `Mcp__Path`, например:
   `https://<app>.up.railway.app/mcp-9f3k2a`

Это и есть уход с публичного ngrok: адрес постоянный, токен в переменных окружения Railway,
а неугадываемый путь закрывает эндпоинт от случайных заходов.

### Вариант Б — ngrok (быстрый тест с локальной машины)

```bash
ngrok http 5000
```
Если адрес сменился — удали и заново добавь коннектор в Claude с новым URL + путь.

---

В обоих случаях: добавь/обнови коннектор в Claude с полным URL (адрес + путь),
переподключи его в диалоге (список инструментов обновляется).

## 5. Аудит

В диалоге с Claude (коннектор включён) дай аудит-промпт — Claude вызовет `wb_audit_dataset`
и построит разбор по SKU и план.

## Инструменты

| Инструмент | Что отдаёт |
|---|---|
| `ping` | проверка связи |
| `wb_get_catalog` | полный каталог (включая товары без продаж) |
| `wb_get_sales` | сводка продаж за период |
| `wb_get_stocks` | остатки по складам/SKU |
| `wb_get_finance` | детализация реализации (к перечислению, логистика, хранение, штрафы) |
| `wb_get_prices` | цены и скидки |
| `wb_get_funnel` | воронка показы→корзина→заказы→выкуп |
| `wb_get_ad_stats` | расход рекламы, показы, клики, заказы |
| `wb_get_feedbacks` | рейтинг и число отзывов |
| `wb_get_orders` | заказы за период (спрос, отдельно от выкупа) |
| `wb_get_incomes` | поставки и товар в пути |
| `wb_get_warehouse_remains` | остатки по складам (async-отчёт) — для распределения отгрузок |
| `wb_get_paid_storage` | платное хранение (async-отчёт) — расход |
| `wb_get_weekly_pnl` | **еженедельный P&L по отчётам о реализации (до себестоимости)** |
| `wb_audit_dataset` | **единая таблица по SKU + паспорт данных** |

Категория токена для новых инструментов: заказы/поставки/P&L — **Статистика**; склады/хранение — **Аналитика**.

## Важное

- **Токен нигде не светится** — только в заголовке запроса из сервера; в ответы, логи и HTML не попадает.
- **Паспорт данных** в каждом ответе: пустой ответ или отказ прав — это НЕ «ноль продаж».
- **Лаги:** воронка −20–30 мин, реклама не за сегодня, финотчёт по неделям.
- **Безопасность:** токен охватывает финансы. На публичном ngrok это критичная экспозиция даже при read-only.
  Перед регулярной работой поставь OAuth на коннектор или уведи эндпоинт с публичного ngrok. Первый прогон — короткой сессией.

## Чего сервер НЕ делает (данные приходят иначе)

- **Себестоимость, упаковка, налоги** — API не отдаёт; подкладывай CSV, join по nmID делает Claude.
- **Джем / сравнение карточек конкурентов** — через обычный токен недоступно; грузи выгрузкой XLSX.

## Проверить при первом запуске (схемы WB местами расходятся между версиями)

Поля читаются защищённо, но если какой-то источник вернёт пусто при явном наличии данных —
сверь путь/поля со Swagger на https://dev.wildberries.ru/en/openapi/api-information. Кандидаты на сверку:
воронка v3 (имена полей в `statistic.selected`), finance detailed (v5 statistics-api vs finance-api),
цены `/api/v2/list/goods/filter`.

## Следующие решения (пока НЕ реализованы — требуют твоего выбора)

- **Записывающий слой** (ответы на отзывы, корректировка ставок) — только через подтверждение человеком на каждое действие, с логом. Массовую смену цен, автосоздание поставок и акции в автономию не отдавать.
- **Мульти-кабинет** — переключение токена/кабинета и консолидированная картина по твоим четырём кабинетам. Смена архитектуры (хранение нескольких токенов), поэтому отдельным заходом.
- **Поисковые запросы и география спроса** — менее стабильные эндпоинты аналитики, сверить со Swagger перед реализацией.
- **OAuth на коннекторе / уход с публичного ngrok** — условие перед регулярной работой с реальным токеном.
